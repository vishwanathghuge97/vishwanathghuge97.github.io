# Kable site

Two static sites, ready to publish as two GitHub Pages repos. No build step,
no dependencies, no JavaScript.

| Folder               | Publishes to                                        | Repo             |
| -------------------- | --------------------------------------------------- | ---------------- |
| `site/` (root files) | https://vishwanathghuge97.github.io/                | `vishwanathghuge97.github.io` |
| `site/kable-download/` | https://vishwanathghuge97.github.io/kable-download/ | `kable-download` |

Each folder holds its own `.nojekyll` (serve files as-is) and a `robots.txt`
that disallows all crawling (`User-agent: *` / `Disallow: /`). The pages also
carry a `noindex, nofollow` meta tag, so they should stay out of search results.

## Preview locally

    python3 -m http.server 8765 --directory site

Then open:

- http://localhost:8765/                  — apps index
- http://localhost:8765/kable-download/   — Kable download page

Relative links are used throughout, so the pages also work from `file://`.

## Publishing (later, not done yet)

Copy the **contents** of `site/` (not the `kable-download/` folder) into the
`vishwanathghuge97.github.io` repo, and the contents of `site/kable-download/`
into the `kable-download` repo. Each folder is self-contained; the index still
links to `kable-download/…` on the same origin.

`latest.json` is **not** part of this folder and must never be created or
edited by hand. It is generated by the release tool during a release. If it is
missing or wrong, regenerate it with the release tool — do not write one.

The two `404.html` files are served by GitHub Pages for unknown paths, so they
use **root-relative** links (`/`, `/kable-download/`) instead of relative ones.
That keeps them working at any URL depth. They preview fine over
`python3 -m http.server` (open `/404.html` or `/kable-download/404.html`), but
`file://` won't resolve root-relative paths.

## Release-day checklist

Publishing the two sites as the two GitHub Pages repos. No secrets, tokens or
key paths are involved or belong in either repo.

1. Publish `site/kable-download/` first, then `site/`:
   - Copy the **contents** of `site/kable-download/` into the `kable-download`
     repo, keeping `.nojekyll` and `robots.txt`. Commit and push.
   - Copy the **contents** of `site/` (not the `kable-download/` folder) into
     the `vishwanathghuge97.github.io` repo, keeping `.nojekyll` and
     `robots.txt`. Commit and push.
2. Confirm the APK: the `kable-download` repo's latest GitHub Release must
   carry an asset named exactly `kable.apk`. The download button on the page
   points at `https://github.com/vishwanathghuge97/kable-download/releases/latest/download/kable.apk`.
   Tap it (or open it in a browser) and confirm the download starts.
3. Confirm `latest.json` is the file produced by the release tool during the
   release, not something hand-created or hand-edited. If it is missing or
   does not look like tool output, stop and regenerate it with the tool — do
   not patch it by hand.
4. Check both published HTTPS pages:
   - https://vishwanathghuge97.github.io/ — index loads; Kable card links to
     `kable-download/`; GitHub footer link works.
   - https://vishwanathghuge97.github.io/kable-download/ — page loads; icon
     and QR render; **Download for Android** starts the APK download; setup
     steps and links are intact.
5. Point a phone camera at the QR code on the published Kable page and confirm
   it opens `https://vishwanathghuge97.github.io/kable-download/`.
6. Confirm both repos contain `.nojekyll` (so Pages serves files as-is), and
   that neither repo contains keys or any other secrets (they don't, by
   construction — keep it that way).
7. If you renamed or moved anything, check `404.html` on both sites: it should
   load and its links should work from any unknown URL.

## QR code

`site/kable-download/qr.svg` encodes `https://vishwanathghuge97.github.io/kable-download/`.
It uses a 4-module quiet zone, black modules on white, and no logo overlay,
so any scanner should read it.

It was generated with the `qr` Dart package (already declared in
`cli/pubspec.yaml`) via a throwaway script in `/tmp` — nothing in `cli/` was
changed. If the page URL ever changes, regenerate the SVG the same way; do not
hand-edit it.

## Icons and favicon

`site/kable-download/icon.png` and `site/icon.png` are both copies of
`assets/kable_icon_512.png`; `icon.png` is the Kable card in the root index
(Kable's real icon). Each folder ships its own copy so neither repo depends
on the other's assets.

The root site's tab icon is `site/favicon.svg` (and its rendered copy
`site/favicon.png`): the same teal rounded square and dark swap-arrows mark
used by the header logo in `index.html`, used by `index.html` and
`404.html`. `site/callapp-icon.svg` is callApp's launcher icon (cream
speech bubble carrying the phone handset on `#0B5568`, per callApp's own
`ic_launcher_foreground.xml` and `colors.xml`), used by the callApp card in
the root index.
